## Block 2 · DONE 19 September · Make "installable" mean something

**Shipped and verified on 19 September.** Nine tools plus the home page are precached, 41 files
and 518 KB, and `tests/offline.browser.cjs` proves a real offline reload of the tuner, a share
link restoring a ledger offline, the home page as the installed app's start url, and the
fallback for a page outside the precache. The softened copy has been restored, because it is
now true. What follows is the design, kept because the reasoning still governs any change to it.

The site installed, but nothing worked after a reload without a connection, because `sw.js`
cached only `/offline`. That is why four pieces of copy had to be softened in the review. The
fix was cheap: the nine light tools together are about **200 KB** of CSS and JavaScript.

The trap to design around: **Cloudflare Pages ignores the query string when serving a file**,
so `/assets/tuner-metronome.js?v=<old hash>` returns the *current* file. Verified on
19 September. A cache keyed on a versioned URL can therefore hold content that no longer
matches the page that asked for it. The cure is to cache each page **together with its own
assets, as one unit, per build**.

Design:

1. **`build.py`** writes `dist/offline-manifest.json` while it renders. As it emits each tool
   page it already knows that page's asset URLs, including the `?v=` hashes; collect them.
   Shape:

   ```json
   { "build": "<sha1 of shell.css + every emitted asset, first 12 hex>",
     "pages": { "/tools/tuner-metronome/": ["/tools/tuner-metronome/", "/assets/shell.css?v=..", "..."] } }
   ```

   Include a page only when its `meta.json` carries `"offline": true`.
2. **Opt in** these nine, all small: `cv-builder`, `subscription-finder`, `qr-codes`,
   `invoice-generator`, `worth-it-calculators`, `settle-up`, `tuner-metronome`,
   `screen-recorder`, `gpx-route-builder` (172 KB, the largest of them).
   **Leave out** `pdf-sign` (2.3 MB), `image-converter` (2.0 MB), `measurement-notebook`
   (0.5 MB, hidden), `background-remover` (16.6 MB), `transcription` (21.9 MB, and it owns its
   own model cache), and `drive-storage-analyser` (it needs the network by definition).
   Keep the total precache under about 500 KB and state the budget in a comment.
3. **`shell/sw.js`**, rewritten around the manifest:
   - `install`: fetch `/offline-manifest.json`, open `pot-app-<build>`, `addAll` every listed
     URL plus `/offline`, then `skipWaiting`.
   - `activate`: delete every cache whose name starts `pot-app-` or `pot-offline-` and is not
     the current one, then `clients.claim()`.
   - `fetch`, navigations: network first; on failure, `caches.match` the navigation URL, then
     `/offline`, then a 503.
   - `fetch`, everything else: if the exact request URL is in the current cache, serve it from
     there; otherwise **return without calling `respondWith`**, so the request goes to the
     network untouched. That keeps range requests, the transcription model cache and every
     tool's own worker out of the way.
   - A per build cache name means a new deploy precaches the new build and drops the old one on
     activate, and a page in cache `pot-app-A` only ever references assets also in `pot-app-A`.
4. **Failure mode to test:** if any URL in `addAll` 404s, the service worker never installs.
   The registration in `shell/page.html` already swallows that, so the site still works, but
   confirm it and log a console warning rather than failing silently.
5. **Verify** with the Chrome MCP: load the tuner, go offline (`emulate` with network
   conditions, or CDP `Network.emulateNetworkConditions` with `offline: true`), reload, confirm
   the page renders and `window.__tuner.detectPitch` still answers. Repeat for Settle Up,
   including restoring a ledger from a share link while offline. Then go back online, deploy a
   trivial change, and confirm the old cache is gone and the new assets are served.
6. **Then restore the wording** for the opted in tools only: the tuner's `meta.json`,
   `tools.json` tagline, `vs/guitartuna.json` and `docs/distribution/alternativeto.md` may say
   "works offline once loaded" again, and the tuner page note can be simplified. Tools left out
   keep the honest phrasing.

**Done when:** the tuner and Settle Up both survive a reload with the network off, a redeploy
replaces the cache, `caches.keys()` shows exactly one `pot-app-*`, and the restored copy is
true.

## Block 3 · DONE 19 September · Tool #18 Habit Tracker

**Shipped and verified live on 19 September** at `/tools/habit-tracker/` with `/vs/habitify/`,
precached for offline use. 13 unit tests plus `tests/habit-tracker.browser.cjs`. What follows is
the brief it was built from.

Slug `habit-tracker`, name **Habit Tracker**. Slate 2 row 18. Check `ls tools/` first; if Codex
has taken it, do Block 4 and then slate item #14.

**Comparison page.** Use Habitify as the incumbent (`vs/habitify.json`) unless a fetch of
https://www.habitify.me/pricing shows its free tier is no longer capped, in which case use
Productive or HabitNow. Verify the free habit cap and the monthly, yearly and lifetime prices
from the incumbent's own page before writing a number. Be fair: what the paid apps really sell
is cross device sync, home screen widgets and health data integration. A web page cannot do any
of those, and the widgets are exactly why app candidate A4 exists on the apps track.

**Build.**

- Habits with a name, a colour, a schedule (every day, chosen weekdays, or N times a week) and
  an optional note. Reorder, archive, delete with a confirm.
- Today view: one row per habit due today, with a tick that updates the streak at once, and a
  seven day strip per habit whose ticks can be toggled retrospectively.
- Streaks: current and best, computed against the schedule so a rest day does not break one.
  Completion rate over the last 30 days.
- A calendar heatmap of the last 52 weeks per habit, as a CSS grid or a canvas.
- State in local storage under `pot:habit-tracker:v1`. A year of ticks for ten habits is a few
  kilobytes. **JSON export and import** (import validates first, then offers merge or replace)
  and **CSV export** of ticks.
- Reminders: only what a page can honestly do. If `Notification` is available, offer a daily
  time that fires while the page or the installed app is open, and say plainly on the page that
  a closed tab cannot remind you and that background reminders and widgets are what the paid
  apps sell. No push server, ever.
- Mark it `"offline": true` so Block 2 precaches it; this is the tool people open first thing
  in the morning, sometimes with no signal.
- A sample button loading three habits with 60 days of plausible ticks.
- Pure logic in `static/core.js` (UMD): `isDue(habit, date)`, `streaks(habit, ticks, today)`,
  `completionRate`, `heatmapCells`, `validate`, `exportJson` and `importJson`, `csv`, `sample`.
  Tests in `tests/habit-tracker.test.cjs`: streaks across rest days, across a month boundary and
  across a year boundary, N per week schedules, completion rate, import rejecting malformed data
  and foreign ids, CSV quoting, and an export then import round trip. Apply the review rules
  above: validate everything imported, and test the edges of every date calculation.
- `window.__habits` hook.

**Done when:** tests pass, the live page loads the sample, a tick survives a reload, export then
import restores the same state, `/vs/habitify/` returns 200, no console errors, and `tools.json`
is flipped to live with `"vs": "habitify"`.

## Block 4 · DONE 19 September · Tool #22 Ringtone Maker

**Shipped and verified live on 19 September** at `/tools/ringtone-maker/` with
`/vs/ringtone-apps/`. 11 unit tests plus `tests/ringtone-maker.browser.cjs`, which decodes a real
file through the file input, checks the waveform is painted, exercises the limits and the keyboard,
plays the preview and reads the bytes of both exports. **No `.m4r`:** AAC encoding is unavailable
in this Chrome, so the page explains the free GarageBand route rather than shipping a button that
would silently fail. Not precached, because the MP3 encoder alone is 156 KB. What follows is the
brief it was built from.

Slug `ringtone-maker`, name **Ringtone Maker**. Slate 2 row 22. Anchor paywall: the ringtone
apps in the Australian Music chart on weekly plans. Open the App Store page of the top result
for "ringtone maker" on apps.apple.com/au and quote its actual in app purchase list in
`vs/ringtone-apps.json`, naming the incumbent as the listing names it. Be fair: an app installs
the tone in one tap and a web page cannot, so the install steps are the honest cost of free.

**Build.**

- Open any audio or video file; `decodeAudioData` handles MP3, M4A, WAV and most MP4 audio.
  Waveform on a canvas, draggable start and end handles, numeric fields, snap buttons for 30 s
  and 40 s (iPhone allows 40 s for a ringtone and 30 s for an alert tone), fade in and out, and
  a looping preview through the Web Audio API.
- Export, in this order, each with feature detection and an honest label:
  1. **M4R and M4A**: `AudioEncoder` from WebCodecs with codec `mp4a.40.2`, muxed by a vendored
     MIT MP4 muxer. If `AudioEncoder.isConfigSupported` says no, hide the button and say why.
  2. **WAV**, always, by writing the RIFF header directly. Android accepts WAV as a ringtone.
  3. **MP3** via vendored `lamejs` (LGPL, ship the notice) only if there is time. Leave it out
     rather than half done.
- Install steps on the page. iPhone: AirDrop or download the `.m4r`, then GarageBand, Share,
  Ringtone; or connect to a Mac and drag it into the device's Tones in Finder. Android: save the
  file, then Settings, Sound, Phone ringtone, pick from Files.
- Pure logic in `static/core.js`: `wavEncode(channels, sampleRate)`, `trimRange`, `fadeCurve`,
  `normaliseGain`, `clampRingtoneLength(kind)`. Tests: WAV header bytes and byte length, fades
  that start and end at exactly zero, trim boundaries including a zero length selection, and the
  40 s and 30 s clamps.
- `window.__ringtone` hook. Mark it `"offline": true` only if the vendored muxer keeps the tool
  under about 150 KB.

**Done when:** a ten second WAV produced by `wavEncode` decodes back to the right length in a
node test, the live page trims and previews with no console errors, the M4R path either works in
Chrome or is hidden with its reason shown, and `tools.json` is flipped.
