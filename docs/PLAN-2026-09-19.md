## Block 1 · Agent · 90 min · Tool #13 Settle Up

Slug `settle-up`, name **Settle Up**. Replaces Splitwise and Tricount. Comparison page
`vs/splitwise.json`: Splitwise caps free users at about four expenses a day and sells Pro at
US$4.99 a month or US$39.99 a year; be fair that Pro's receipt scanning, charts and the
multi device sync are real value for people who split costs every day. Sources are in
`~/dev/idea-engine/SLATE2.md` row 13; re-verify the cap and price with a quick web fetch
before writing the page.

Build:

- People (names), expenses (payer, amount, date, note, split equally or by custom shares),
  running balance per person, and a **settle up plan**: the minimal set of transfers that
  clears all balances (greedy: repeatedly match the largest debtor with the largest creditor).
- Currency symbol picker (A$, $, £, €), two decimal money handling in integer cents.
- Whole ledger encoded into the URL hash (JSON, base64url) so a **Copy link** button shares
  the group with no server; opening the link restores it. Autosave to localStorage key
  `pot:settle-up:v1`. CSV export of expenses and of the settlement plan. Print friendly.
- A **Try it with a sample** button (a fictional weekend trip, five people, eight expenses).
- Pure logic (balances, settlement, encode/decode) in `static/core.js` as a UMD module loaded
  by a script tag in `index.html`, so `tests/settle-up.test.cjs` can `require` it. Follow the
  pattern Codex used in `tools/transcription/static/core.js`. Tests: balances sum to zero,
  settlement clears every balance, encode/decode round trip, custom shares that do not sum
  to the total are rejected with a message.
- Expose `window.__settleup` with the core functions for browser checks.

Done when: tests pass, page live at https://plentyoftools.io/tools/settle-up/ with the sample
loading and a share link that restores the ledger in a fresh tab, `/vs/splitwise/` returns
200, no console errors, `tools.json` flipped to `live` with `"vs": "splitwise"`.

## Block 2 · Agent · 75 min · Tool #17 Tuner and Metronome

Slug `tuner-metronome`, name **Tuner and Metronome**. Replaces GuitarTuna, Tuner Pro and
the metronome apps with subscriptions. Comparison page `vs/guitartuna.json`: GuitarTuna's
free tier is ad supported with the alternate tunings and chord library behind a subscription;
verify current pricing with a web fetch before writing, and be fair that its lessons and
song library are the paid product, not the tuner.

Build, no libraries:

- **Tuner:** microphone via `getUserMedia`, `AnalyserNode` time domain data, pitch by
  autocorrelation (McLeod style normalisation is fine), nearest note name, cents offset on a
  needle, frequency readout, smoothing over a few frames, silence gate. Reference A4
  adjustable (440 default, 415 to 466). Instrument presets that highlight target notes:
  guitar standard, drop D, bass, ukulele, violin, plus chromatic. Click a string name to hear
  its reference tone (oscillator, short envelope).
- **Metronome:** Web Audio lookahead scheduler (never `setInterval` for the clicks), BPM 30 to
  300 with a slider, number field and tap tempo, time signatures 2/4, 3/4, 4/4, 6/8, accent
  on beat one, subdivisions (quarter, eighth, triplet), visual beat dots, space bar toggles,
  tempo marking shown (Adagio, Andante, Allegro...). Settings persist in localStorage
  `pot:tuner-metronome:v1`.
- Microphone permission text on the page, and a clear message when the browser blocks it.
  Works offline once loaded.
- Expose `window.__tuner` with the pitch detection function and the note mapping so a browser
  check can feed it a synthetic 440 Hz buffer and expect "A4, 0 cents".

Done when: the synthetic pitch check passes in the live page, the metronome runs at a stable
tempo for a minute (check `AudioContext.currentTime` drift in a console evaluation), the
comparison page is live, `tools.json` flipped.

## Block 3 · Agent · 45 min · Make the site installable

- `shell/manifest.webmanifest`: name "Plenty of Tools", short name "Tools", start URL `/`,
  display standalone, background and theme colours matching `shell.css` tokens, icons at
  192 and 512 px. The icons already exist in `shell/icons/` (`logo-192.png`, `logo-512.png`,
  `logo-maskable-512.png` for the maskable purpose, `favicon.ico`, `favicon-32.png`,
  `logo.svg`); copy them, do not regenerate. Add `<link rel="icon">` for the favicon too.
- `shell/sw.js`: minimal and safe. Install does `skipWaiting`; fetch handler is network
  first with no caching of tool assets (several tools ship workers and wasm; a caching
  service worker would serve stale code after deploys). Precache one `offline.html` and
  return it when navigation fetch fails.
- `shell/page.html`: add `<link rel="manifest">`, `<meta name="theme-color">`, an Apple
  touch icon, and a guarded `navigator.serviceWorker.register('/sw.js')`.
- `build.py`: copy the manifest, service worker, offline page and icons to the `dist` root.
  Targeted patch next to the existing `shell.css` copy.

Done when: Chrome's install prompt appears for https://plentyoftools.io (check the
`beforeinstallprompt` event fires or the install icon shows in the address bar), Lighthouse's
installability audit passes, and every tool still works with the service worker active,

## Block 4 · Agent · 30 min · Cache busting for assets

The zone caches `/assets/*` for four hours (`max-age=14400`), so a deploy can leave old
JavaScript on the custom domain for returning visitors. In `build.py`, append
`?v=<first 8 hex of the file's sha1>` to every per tool CSS, JS and vendor script URL it
emits, and to the `shell.css` link in `shell/page.html` via a template token. Targeted
patches only. Rebuild, deploy, confirm the query strings appear in the live HTML and the
pages still load.
